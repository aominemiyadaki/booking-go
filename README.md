# 📅 Booking Backend (Go)

Высоконагруженный бэкенд-сервис для платформы онлайн-записи и бронирования услуг (мастера, клиенты, расписания, учет перерывов и слотов). Спроектирован по принципам **Clean Architecture** с полным разделением слоев, валидацией контрактов и интерактивной документацией Swagger.

---

## 📌 Какая стояла задача и какую боль закрывали

### Проблема (Боль):
В сервисах бронирования услуг ключевая сложность — это **расчет доступных слотов и предотвращение овербукинга (двойной записи)**. 
- У каждого мастера индивидуальный график работы и плавающие перерывы разного типа.
- Услуги имеют разную продолжительность.
- При одновременной записи нескольких клиентов на соседние слоты возникает риск коллизий.
- Необходим учет проблемных клиентов (Blacklist) и строгая изоляция данных.

### Решение:
- Спроектирован отказоустойчивый движок расчета временных окон без пересечений.
- Бизнес-логика вынесена в чистый сервисный слой, изолированный от деталей HTTP и БД.
- Работа с базой организована через `pgx/v5` с пулом соединений `puddle` и транзакциями.
- Авторизация построена на базе JWT (stateless) с безопасным хэшированием паролей через `bcrypt`.

## 🏗 Архитектура и схема потоков данных

Проект следует классическому шаблону многослойной архитектуры (Layered / Clean Architecture):

```
                      [ HTTP Client / Mobile App ]
                                    │
                                    │ REST API + Bearer Token
                                    ▼
                ┌──────────────────────────────────────┐
                │        Gin HTTP Router / Engine      │
                │  - Logger & Recovery Middleware      │
                │  - JWT Auth Middleware               │
                │  - Swagger UI Documentation          │
                └──────────────────┬───────────────────┘
                                   │
                                   ▼
                ┌──────────────────────────────────────┐
                │          Delivery / Handlers         │
                │  - Декодирование JSON                │
                │  - Валидация (validator/v10)         │
                │  - Маппинг в DTO                     │
                └──────────────────┬───────────────────┘
                                   │
                                   ▼
                ┌──────────────────────────────────────┐
                │             Service Layer            │
                │  - Проверка пересечения интервалов   │
                │  - Проверка мастера и клиента        │
                │  - Проверка Blacklist                │
                │  - Генерация JWT токенов             │
                └──────────────────┬───────────────────┘
                                   │
                                   ▼
                ┌──────────────────────────────────────┐
                │           Repository Layer           │
                │  - SQL-запросы через pgx/v5          │
                │  - Транзакционный контроль           │
                │  - Коннекшн-пул (puddle/v2)          │
                └──────────────────┬───────────────────┘
                                   │
                                   ▼
                       [ PostgreSQL Database ]
```

## 🛠 Используемые библиотеки и стек

| Компонент / Пакет | Назначение |
|---|---|
| **Go 1.23+** | Основной язык разработки (горутины, каналы, контексты) |
| **`github.com/gin-gonic/gin`** | Быстрый HTTP-фреймворк и роутинг запросов |
| **`github.com/jackc/pgx/v5`** | Нативный драйвер PostgreSQL с высокой производительностью и пулом соединений |
| **`github.com/golang-jwt/jwt/v5`** | Выпуск и верификация токенов аутентификации |
| **`golang.org/x/crypto/bcrypt`** | Криптографически стойкое хэширование паролей |
| **`github.com/swaggo/gin-swagger`** | Автогенерация спецификации OpenAPI и интерактивный UI |
| **`github.com/go-playground/validator/v10`** | Декларативная валидация структур и полей запросов |
| **Grafana / Prometheus** | Провижининг телеметрии и дашбордов (`telemetry/grafana`) |

## 📁 Структура проекта

```
.
├── cmd/
│   └── api/                # Точка входа приложения (main.go, инициализация зависимостей)
├── internal/
│   ├── config/             # Загрузка и валидация конфигурации окружения
│   ├── database/           # Инициализация подключения к БД (pgxpool)
│   ├── handler/            # HTTP-хендлеры, middleware (auth, logger, recovery)
│   ├── service/            # Доменная бизнес-логика (appointments, schedule, masters)
│   ├── repository/         # Слой доступа к данным (PostgreSQL queries)
│   ├── models/             # Модели сущностей (appointment, master, client, schedule)
│   └── logger/             # Структурированное логирование
├── migrations/             # SQL-миграции схемы базы данных
├── bruno_collection/       # Сквозная коллекция API-запросов для клиента Bruno
├── telemetry/              # Конфигурация дашбордов мониторинга для Grafana
└── docker-compose.yml      # Локальный подъем PostgreSQL и инфраструктуры
```

## ⚙️ Быстрый старт

### 1. Клонирование и настройка окружения
```bash
git clone https://github.com/aominemiyadaki/booking-go.git
cd booking-go
cp .env.example .env
```

### 2. Запуск PostgreSQL
```bash
docker-compose up -d postgres
```

### 3. Применение миграций и запуск сервиса
```bash
go run cmd/api/main.go
```
Сервер будет доступен по адресу: `http://localhost:8080`

### 4. Документация API (Swagger UI)
Откройте в браузере:
👉 `http://localhost:8080/swagger/index.html`

### 5. Тестирование через Bruno
В проекте есть папка `bruno_collection/` — импортируйте ее в API-клиент [Bruno](https://www.usebruno.com/) для удобного тестирования всех эндпоинтов (авторизация, расписание, слоты, бронирование).
